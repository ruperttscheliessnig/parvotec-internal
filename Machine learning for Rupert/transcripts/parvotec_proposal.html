Executive Summary

Parvotec entwickelt einen AAV-Vektor mit selektivem Tropismus für nozizeptive Neuronen (Dorsal Root Ganglia, DRG) und effizienter retrograder Transportkapazität als Plattform für periphere Schmerzgentherapie.

Das zentrale technologische Differenzierungsmerkmal ist ein ML-gesteuerter iterativer Design-Evaluate-Optimize-Loop: ein sogenanntes Fitness Oracle — ein trainiertes neuronales Netzwerk, das aus Proteinsequenz-Embeddings (ESM-2/ESM-3) mehrere biologische Zieleigenschaften gleichzeitig vorhersagt und als Surrogate für kostspielige experimentelle Assays dient.

Kernhypothese: Durch Kombination von experimentellem Deep Mutational Scanning (DMS), Protein Language Model Embeddings (ESM-2), konditionaler generativer Modellierung (cVAE) und Multi-objective Bayesian Optimization kann in 3–4 iterativen Runden ein nozizeptiver DRG-spezifischer AAV-Vektor mit 5–10× verbessertem Tropismus gegenüber Wild-type identifiziert werden.

Wettbewerbskontext (ASGCT 2026)

Vier konkurrierende Programme wurden auf der ASGCT 2026 präsentiert:

  • Exgenesis Bio (EXG117): AAV-RNAi gegen Nav1.7 in DRG. Klinisch validiertes Konzept, aber traditioneller Capsid-Design (kein ML-Ansatz). Nachteil: Nav1.7-spezifisch, kein generische Capsid-Plattform.
  • SereNeuro (SN102): KCNQ2 Base Editing via iPSC-Sensory-Neuron-Modell. Innovativer Genomics-Ansatz, aber frühe klinische Phase. Capsid-Engineering nicht fokussiert.
  • Sangamo / Encoded: Etablierte AAV-Vektoren für Schmerzindikationen. Fortgeschrittene klinische Daten, aber kein ML-optimierter Capsid.
  • Sanofi GMU037: ML-getriebener Capsid-Ansatz für Leber. Direkt relevanter Ansatz, jedoch anderes Gewebe-Targeting.

Parvotec Alleinstellungsmerkmal: Einziger Ansatz mit ML-optimiertem AAV-Capsid spezifisch für nozizeptive Neuronen + retrograden Transport. Direkter Wettbewerb mit WhiteLab CapsidFlow und PackGene π-Icosa im Methodik-Bereich.

Fitness Oracle — Datenpipeline

Das Oracle ist so gut wie seine Trainingsdaten. Diese Sektion beschreibt den gesamten Datenfluss von rohen experimentellen Daten bis zum bereinigte ML-Dataset.

Datenverarbeitungsschritte

  1. Raw NGS Data: Illumina FASTQ-Dateien. Demultiplexing nach Barcode. Adapter-Trimming (Cutadapt). Qualitätsfilter: Q-Score ≥20, Coverage ≥10 Reads/Variante.
  2. Variant Calling: Alignment der Barcode-Reads gegen die Design-Library. Frequenzberechnung: freq(i) = Reads(i) / TotalReads. Separate Frequenzmatrizen für Pre-Selection und Post-Selection.
  3. Enrichment Score Berechnung: log2(freq_post / freq_pre). Pseudocount = 1/TotalReads zur Division-by-Zero Vermeidung. Normalisierung: z-Score innerhalb jedes Experiments (μ=0, σ=1).
  4. Sequenz-Extraktion: Barcode → Aminosäuresequenz Mapping via Design-Library Lookup. Validierung: Alle 20 kanonischen Aminosäuren, keine Stop-Codons, korrekte Länge (7-Mer Insert).
  5. Multi-Label Fusion: Merge der In-Vitro DRG, In-Vivo Retrograd, und Yield-Assay Daten per Sequenz-ID. Missing Labels: Multiple Imputation via missForest. Final Dataset enthält 4 Scores pro Variante.
  6. Train/Val/Test Split: Stratified Split nach Enrichment-Quartil (Q1–Q4) und Insert-Position. Verhältnis: 70 / 15 / 15. Kein Data Leakage: Sequenzen mit ≥80% Identität zur Test-Set werden aus Training entfernt.
  7. ESM-2 Batch Embedding: Full-length VP1-Sequenz (733 AA) + Insert. Batch Size = 32 (GPU-Speicher-limitiert). Output: 1280-dim Mittelwert über alle Token-Positionen (mean pooling). Pre-computed und gespeichert als float16 HDF5.

Qualitätskontrolle Dataset

Go-Kriterien für WP3 Start: ≥500k validierte Sequenz-Enrichment-Paare, ≥50k Varianten mit allen 4 Labels (Multi-task Training), Library Coverage ≥80% (d.h. ≥80% der designten Varianten detektiert), Spearman-Korrelation technische Replikate ≥0.85.

# Beispiel: Enrichment Score Berechnung
import numpy as np
import pandas as pd

def compute_enrichment(pre_counts: pd.Series,
                        post_counts: pd.Series,
                        pseudocount: float = 1.0) -> pd.Series:
    """Log2 enrichment mit Pseudocount für Coverage-Normalisierung."""
    freq_pre  = (pre_counts  + pseudocount) / (pre_counts.sum()  + pseudocount)
    freq_post = (post_counts + pseudocount) / (post_counts.sum() + pseudocount)
    return np.log2(freq_post / freq_pre)

# Normalisierung: z-Score innerhalb Experiment
def zscore_normalize(enrichment: pd.Series) -> pd.Series:
    return (enrichment - enrichment.mean()) / enrichment.std()

Schicht 2: Fitness Predictor NN

Das Herzstück des Oracle: ein Multi-task Feed-Forward Neural Network das vier biologische Properties aus ESM-2 Embeddings vorhersagt.

class FitnessPredictor(nn.Module):
    """
    Multi-task Fitness Predictor.
    Input:  ESM-2 embedding R^1280
    Output: 4 property scores [tropism, yield, stability, immunogenicity]
    """
    def __init__(self, emb_dim=1280, hidden=[512, 256, 128], dropout=0.15):
        super().__init__()
        layers = []
        in_dim = emb_dim
        for h in hidden:
            layers += [nn.Linear(in_dim, h), nn.ReLU(), nn.Dropout(dropout)]
            in_dim = h
        self.backbone = nn.Sequential(*layers)
        # Separate heads für bessere Task-spezifische Gradienten
        self.head_tropism   = nn.Sequential(nn.Linear(128, 32), nn.ReLU(), nn.Linear(32, 1), nn.Sigmoid())
        self.head_yield     = nn.Sequential(nn.Linear(128, 32), nn.ReLU(), nn.Linear(32, 1), nn.Sigmoid())
        self.head_stability = nn.Sequential(nn.Linear(128, 32), nn.ReLU(), nn.Linear(32, 1), nn.Sigmoid())
        self.head_immuno    = nn.Sequential(nn.Linear(128, 32), nn.ReLU(), nn.Linear(32, 1), nn.Sigmoid())

    def forward(self, x):
        feat = self.backbone(x)
        return torch.cat([self.head_tropism(feat), self.head_yield(feat),
                          self.head_stability(feat), self.head_immuno(feat)], dim=-1)

Schicht 3: cVAE Sequenz-Generator

Der cVAE generiert neue AAV-Sequenzen mit spezifizierten Ziel-Eigenschaften. Er lernt die Verteilung von bekannt-guten Sequenzen und kann daraus neue interpolieren.

class AAVcVAE(nn.Module):
    """
    Conditional Variational Autoencoder für AAV 7-Mer Insert Generation.
    Input:  Insert-Sequenz (7 AA, one-hot = 7×20 = 140 dim) + Condition (4 target scores)
    Latent: R^128
    Output: Insert-Sequenz (7×20 Wahrscheinlichkeiten, softmax)
    """
    def __init__(self, seq_dim=140, cond_dim=4, latent_dim=128):
        super().__init__()
        # Encoder: Sequenz + Condition → μ, logσ²
        self.encoder = nn.Sequential(
            nn.Linear(seq_dim + cond_dim, 256), nn.ReLU(),
            nn.Linear(256, 128), nn.ReLU()
        )
        self.fc_mu     = nn.Linear(128, latent_dim)
        self.fc_logvar = nn.Linear(128, latent_dim)
        # Decoder: Z + Condition → Sequenz-Logits
        self.decoder = nn.Sequential(
            nn.Linear(latent_dim + cond_dim, 256), nn.ReLU(),
            nn.Linear(256, 256), nn.ReLU(),
            nn.Linear(256, seq_dim)  # reshape zu (7, 20) dann softmax
        )

    def reparameterize(self, mu, logvar):
        std = torch.exp(0.5 * logvar)
        eps = torch.randn_like(std)
        return mu + eps * std

    def forward(self, x, condition):
        h = self.encoder(torch.cat([x, condition], dim=-1))
        mu, logvar = self.fc_mu(h), self.fc_logvar(h)
        z = self.reparameterize(mu, logvar)
        recon = self.decoder(torch.cat([z, condition], dim=-1))
        return recon, mu, logvar

    def generate(self, condition: torch.Tensor, n=10, temp=1.0) -> list[str]:
        """Generiert n neue 7-Mer Insert Sequenzen für gegebene Ziel-Scores."""
        z = torch.randn(n, 128) * temp
        logits = self.decoder(torch.cat([z, condition.expand(n,-1)], dim=-1))
        probs  = torch.softmax(logits.view(n, 7, 20) / temp, dim=-1)
        aa     = "ACDEFGHIKLMNPQRSTVWY"
        return [''.join(aa[probs[i,j].argmax()] for j in range(7)) for i in range(n)]

Schicht 4: Multi-objective Bayesian Optimization

Die BO-Schicht koordiniert den iterativen Optimierungsprozess. Sie nutzt das Fitness Oracle als Surrogate-Modell und die Expected Hypervolume Improvement (EHVI) Acquisition Function um multi-objektiv-optimale Kandidaten für das nächste Experiment vorzuschlagen.

# Bayesian Optimization Setup mit BoTorch
from botorch.models import SingleTaskGP
from botorch.fit import fit_gpytorch_model
from botorch.acquisition.multi_objective import qExpectedHypervolumeImprovement
from botorch.utils.multi_objective.pareto import is_non_dominated

def run_bo_iteration(
    X_observed: torch.Tensor,    # Embeddings bisheriger Kandidaten, shape (N, 1280)
    Y_observed: torch.Tensor,    # Gemessene Properties, shape (N, 4)
    ref_point:  torch.Tensor,    # Referenz-Punkt für Hypervolumen, z.B. [0.3, 0.3, 0.3, 0.5]
    n_candidates: int = 50
) -> torch.Tensor:
    """
    Gibt n_candidates Embedding-Vektoren zurück die EHVI maximieren.
    Diese werden dann via cVAE zu Sequenzen rückübersetzt.
    """
    # Baue GP Surrogate für jede Objective
    model = SingleTaskGP(X_observed, Y_observed)
    mll   = ExactMarginalLogLikelihood(model.likelihood, model)
    fit_gpytorch_model(mll)

    # EHVI Acquisition
    pareto_mask = is_non_dominated(Y_observed)
    acq = qExpectedHypervolumeImprovement(
        model=model,
        ref_point=ref_point,
        partitioning=NondominatedPartitioning(ref_point=ref_point, Y=Y_observed[pareto_mask])
    )
    # Optimize acquisition function
    candidates, _ = optimize_acqf(
        acq, bounds=X_bounds, q=n_candidates,
        num_restarts=10, raw_samples=512
    )
    return candidates

Fitness Oracle — Betrieb & API

Standardisierter Optimierungs-Workflow

Jede Optimierungsrunde folgt diesem fixierten Protokoll. Abweichungen müssen dokumentiert werden.

  1. Kandidaten-Generierung (Tag 1). cVAE.generate(condition=[tropism=0.85, yield=0.80, stab=0.80, immuno=0.20], n=500, temp=0.8). Deduplizierung (Levenshtein-Distanz ≥3). Validierung: nur natürliche Aminosäuren, korrekte Insertionsstelle. Fitness Oracle Screening aller 500 Kandidaten. Ranking nach gewichtetem Score.
  2. BO-Kandidaten-Selektion (Tag 1). run_bo_iteration() gibt 50 Embedding-Vektoren zurück die EHVI maximieren. Nearest-Neighbor-Lookup in ESM-2 Embedding Space → 50 reale Sequenzkandidaten. Review: Manuelle Prüfung der 50 Kandidaten auf biochemische Plausibilität.
  3. Experimentelle Validierung (Tag 2–28). Bestellung der 50 Kandidaten als synthetische Gensequenzen (Twist Bioscience, Integrated DNA Technologies). rAAV-Produktion (triple transfection, HEK293T, 5 T175 Flaschen/Kandidat). Titer: ddPCR, Ziel ≥5×10^12 vg/mL. Assays: FACS Tropismus (DRG Neuronenkulturen), qPCR Transgene Expression, DSF Thermostabilität.
  4. Data Integration (Tag 28–30). NGS/FACS Rohdaten → Enrichment Score Berechnung (wie WP2 Pipeline). Merge mit Oracle-internem Dataset. Re-Training des Fitness Predictors auf allen kumulierten Daten (Runden 0 + aktuell). Update der BO-Surrogate GP-Modelle.
  5. Pareto-Front Update (Tag 30). Berechnung der Pareto-Front aller je getesteten Kandidaten. Visualisierung als 3D-Plot (Tropismus vs Yield vs Stabilität). Auswahl der Top-N non-dominated Kandidaten für nächste Runde oder finale Validierung.
