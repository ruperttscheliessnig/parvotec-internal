PARVOTEC–CALYRAI Programme v1.0

Programme Overview

Parvotec develops a multi-objective AAV capsid design system — from a reproducible Fit4Function baseline to a closed ML-guided optimisation loop for nociceptive DRG neuron therapy.

Core Distinction: PARVOTEC is not a renamed Fit4Function. Fit4Function is the reproducible methodological starting point. The MVP closes one prospective assay–NGS loop. The target is a multi-oracle, multi-objective AAV design system.

IP Boundary

The clear separation between CALYR background IP and PARVOTEC project results is mandatory and binding across all work packages.

Rule: No PARVOTEC data or project result may enter reusable CALYR assets without explicit written approval.

ClassificationExamples
calyrai_backgroundGeneric CALYR/Pythia platform architecture · Reusable data, surrogate, uncertainty, and provenance contracts · Pre-existing utilities, templates, and abstract modelling methods
parvotec_project_resultProject-specific AAV data and derived artefacts · Project-specific model implementation, weights, features, and rankings · Project variants, candidates, validation results, and documentation
mixed_with_explicit_boundaryWPs containing both platform and project-result components — IP boundary must be explicitly documented

Evidence Policy

Every model, metric, candidate ranking, and scientific claim must state its evidence level, dataset version, split policy, uncertainty status, and limitations.

LevelMeaning
E0 ConceptConcept or hypothesis; not experimentally established.
E1 BaselineReproduced external baseline with traceable source data and code.
E2 RetrospectiveInternally validated retrospective result with leakage-safe evaluation.
E3 ProspectiveProspective experimental validation against predefined controls.
E4 ReplicatedRepeated closed-loop validation across batches or contexts.

Target AAV Oracle — System Architecture

Learn an experimentally grounded map from AAV sequence and state to manufacturability, functional traits, structural plausibility, and ranked design decisions.

Architecture Principle: PARVOTEC is not a renamed Fit4Function. Each stage builds on the previous and asserts only the truth claim warranted by its evidence level.

O1

Design Space & Constraints

Define sequence region, controls, feasible variants, manufacturability constraints, and experimental budget.

O2

Library & Experiment Design

Select diverse, informative candidates using constrained sampling and computational DoE.

O3

Multi-Modal Observations

Register core assay, NGS, production, and functional observations; accept biophysical observations through optional extension contracts.

O4

Trait-Specific Surrogates

Estimate production fitness and later functional, binding, stability, and structural traits with calibrated uncertainty.

O5 opt.

Biophysical Interpretation

If commissioned and data available: test whether ranked candidates are compatible with solution structure, envelopes, and assembly constraints.

O6

Oracle Fusion & Decision

Combine compatible trait predictions, uncertainty, constraints, diversity, and Pareto ranking without hiding conflicts.

O7

Experimental Validation

Measure selected candidates against controls and record falsifiable success or failure evidence.

O8

Active-Learning Update

Update datasets and models, compare acquisition policies, and select the next experimental batch.

Non-Goals

The following claims are explicitly excluded from this programme. Any attempt to cross these boundaries requires a new scoping decision.

Claims inadmissible within this programme:

  • Claiming clinical efficacy from surrogate or in-vitro evidence
  • Treating structural compatibility as proof of biological function
  • Combining incompatible assays into a single opaque score
  • Promoting exploratory mathematical ideas to validated production logic without evidence
